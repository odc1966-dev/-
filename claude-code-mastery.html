세상에서 클로드 코드를
가장 잘 이해하는 사람이 되는 길

문서를 다 읽는 것으로는 부족합니다. 읽은 것을 재현 가능한 실험으로 바꾸고, 만든 것을 남에게 전수할 수 있을 때 이해가 완성됩니다. 이 커리큘럼은 그 두 가지를 매주 강제합니다.

이해의 다섯 층위 — 대부분은 2층에서 멈춥니다

L1조작 Operate시키면 결과가 나온다. 프롬프트를 쓸 줄 안다.
L2구성 ConfigureCLAUDE.md·settings·권한을 내 환경에 맞춘다.
L3확장 Extend없는 기능을 skill·subagent·hook·MCP로 만든다.
L4해부 Internalize왜 그렇게 동작하는지 측정으로 설명한다. 토큰·캐시·컨텍스트를 회계한다.
L5전수 Create도구를 배포하고, 가르치고, 설계 의도를 서술한다.
주간 리듬 · Weekly rhythm

하루 60~90분, 다섯 가지 다른 종류의 시간

매일 같은 일을 하면 L2에서 멈춥니다. 요일마다 인지 활동의 종류를 바꾸는 것이 이 리듬의 핵심입니다.

월 · 읽기개념 흡수 — 그 주 문서를 읽되, 읽으면서 "이건 어떻게 확인하지?" 질문을 3개 적습니다.
화 · 실험측정 — 월요일의 질문 3개를 실제 세션으로 검증. /context, /cost, 도구 호출 횟수를 기록합니다.
수 · 구축산출물 — 배운 것으로 실제 쓸 물건을 만듭니다. 본인 업무(교육자료·평가·앱)에 붙입니다.
목 · 파괴고장내기 — 일부러 실패시킵니다. 권한 거부, 컨텍스트 초과, 잘못된 훅. 오류 메시지를 수집합니다.
금 · 서술글쓰기 — 그 주 배운 것을 800자로 씁니다. 설명 못 하는 부분이 이해 안 된 부분입니다.
주말캡스톤 — 2~3시간, 아래 세 프로젝트 중 하나를 전진시킵니다.
캡스톤 · Capstone

본인 임상 현장에 붙는 세 개의 프로젝트

이해를 증명하는 것은 시험이 아니라 작동하는 물건입니다. 세 프로젝트는 각각 다른 확장 레이어를 강제합니다.

Skill + Subagent + PPTX

보호자 교육자료 생성 파이프라인

주제·아동 연령·회기 수를 넣으면 서식 규칙(글자 크기·색·여백)이 고정된 슬라이드가 나오고, 별도 서브에이전트가 넘침·비율 붕괴를 검수합니다. Phase 3 완료 시점에 착수.

Agent SDK + MCP

평가도구 데이터 도우미

평가 원점수를 넣으면 해석·목표 초안을 만들고, MCP로 본인 자료 저장소를 읽습니다. 커스텀 도구·구조화 출력·권한 제어를 전부 씁니다. Phase 5에서 착수.

Plugin + Marketplace

신입치료사 온보딩 플러그인

기록 작성 규칙, 세션 노트 템플릿, 용어 검수 훅을 한 플러그인으로 묶어 배포. 남이 설치해 쓰는 순간 L5입니다. Phase 7의 핵심 산출물.

함정 · Common misreadings

대부분이 여기서 잘못 이해합니다

각 항목은 Phase 2·3·6에서 직접 측정해 확인하게 됩니다. 지금은 "그렇다더라"로 읽고, 나중에 본인 숫자로 반박하거나 확인하세요.

CLAUDE.md는 길수록 좋다. 아니오. 매 세션 전량 로드되어 비용이 되고, 지시가 많아질수록 개별 지시의 밀도가 떨어집니다. 짧고 절대적인 규칙 + 경로별 rules/ 분할이 낫습니다.
서브에이전트를 많이 띄우면 빨라진다. 조건부. 각 에이전트는 컨텍스트를 처음부터 다시 쌓고, 결과 병합 비용이 듭니다. 병렬 이득이 재구축 비용을 넘는 작업에만 씁니다.
skill과 슬래시 커맨드는 다른 물건이다. 같은 메커니즘입니다. commands/*.md는 단일 파일, skills/<name>/SKILL.md는 보조 파일을 거느릴 수 있는 디렉터리 형태입니다.
MCP 서버는 많이 붙일수록 좋다. 아니오. 연결된 도구의 스키마가 컨텍스트를 차지합니다. 도구 검색(tool search)으로 지연 로딩하는 구조를 이해해야 합니다.
압축(compaction)은 무손실이다. 아니오. 무엇이 살아남고 무엇이 요약되는지 규칙이 있습니다. 살아남길 원하는 정보는 파일로 내보내야 합니다.
권한을 넓게 열면 편하다. 사고 반경이 넓어집니다. 권한 모드·샌드박스·체크포인트는 셋이 한 세트로 설계되었습니다. 셋의 관계를 설명할 수 있어야 합니다.
훅은 Claude가 실행한다. 하네스가 실행합니다. 그래서 훅은 결정적(deterministic)이고, "매번 반드시"가 필요한 규칙은 지시문이 아니라 훅이어야 합니다.
프롬프트 캐시는 알아서 된다. 앞부분이 흔들리면 전량 무효화됩니다. 무엇이 프롬프트 앞쪽에 놓이는지 알면 비용이 절반이 됩니다.
문서를 읽었으면 이해한 것이다. 재현 실험이 없으면 L3까지입니다. 이 커리큘럼이 실험을 매주 강제하는 이유입니다.
버전 추종은 나중에 해도 된다. 주 단위로 기능이 바뀝니다. 변경 로그(changelog)가 이 도구의 1차 사료입니다. Phase 6에서 12개월치를 역주행합니다.
도구 · Lab notebook

실험 노트 규격

실험 1건 = 커밋 1건. 이 형식을 지키지 않은 실험은 나중에 재현할 수 없고, 재현할 수 없으면 근거가 되지 못합니다.
